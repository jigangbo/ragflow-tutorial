# 第 1 章 背景：零基础理解 RAG

> 本章为零基础读者建立领域概念。已熟悉 RAG 的读者可跳到第 4 节。

## 1. 为什么需要 RAG

大语言模型（LLM）有两个先天缺陷：

- **知识截止**：模型只知道训练数据里的内容，不知道你公司内部文档、最新新闻；
- **幻觉**：被问到不知道的事，它会"编"一个听起来合理的答案。

**RAG（Retrieval-Augmented Generation，检索增强生成）**的解法很朴素：

```
用户提问 → 先从"你的资料库"里检索出最相关的几段文字 → 把这些文字连同问题一起交给 LLM
        → LLM 基于给定材料作答，并标注"这句话来自哪份文档第几页"
```

一句话：**RAG = 开卷考试**。LLM 不再凭记忆答题，而是照着给的参考材料答题。

```
        传统 LLM                     RAG
  ┌──────────────┐          ┌──────────────────────────────┐
  │ 用户提问      │          │ 用户提问                      │
  │      ↓       │          │      ↓                       │
  │  LLM 凭记忆   │          │ 检索器：从知识库找相关段落      │
  │  直接作答      │          │      ↓                       │
  │      ↓       │          │ LLM：基于段落 + 问题作答       │
  │ 易幻觉/过时    │          │      ↓                       │
  └──────────────┘          │ 答案 + 原文引用（可溯源）       │
                             └──────────────────────────────┘
```

## 2. RAG 系统的核心概念（RAGFlow 全部用到）

| 概念 | 一句话解释 | RAGFlow 对应 |
|---|---|---|
| **知识库（Knowledge Base / Dataset）** | 一批文档的容器 | 界面上的"知识库"，API 里叫 dataset |
| **文档解析（Parsing）** | 把 PDF/Word/网页变成机器可读文本 | deepdoc 视觉解析引擎 |
| **分块（Chunking）** | 把长文档切成几百字的小段——检索的最小单位 | 15 种"切片模板"（chunker） |
| **Embedding（向量化）** | 把每段文字变成一串数字（向量），语义相近则向量相近 | q_{维度}_vec 列 |
| **向量检索** | 用"问题的向量"找"最相近的段落向量" | Elasticsearch / Infinity 等引擎 |
| **全文检索** | 传统关键词倒排索引（BM25 类），命中确切术语 | 与向量检索混合使用 |
| **混合检索 + 融合** | 全文分与向量分加权融合，兼顾关键词与语义 | weighted_sum 融合 |
| **Rerank（重排）** | 用更精（更慢）的模型对候选段落二次排序 | 可选配置 rerank 模型 |
| **引用（Citation）** | 答案里标注 `[ID:1]`，点击可看原文截图 | RAGFlow 招牌能力 |
| **GraphRAG** | 把文档抽成"实体-关系"图谱再检索，擅长跨文档推理 | 知识库级开关 |
| **RAPTOR** | 把分块逐层聚类摘要成树，擅长回答"全局性"问题 | 知识库级开关 |
| **Agent（智能体）** | LLM 循环调用工具（搜索/检索/代码）完成复杂任务 | 可视化画布工作流 |

## 3. 一次检索问答的完整旅程

```
(1) 离线：文档 → 解析 → 分块 → 向量化 → 存入搜索引擎
                                            │
(2) 在线：用户问题 ──┬─ 全文检索（关键词命中）──┤
                    └─ 向量检索（语义相近）────┤
                                             ↓
                          融合排序 → 可选 rerank → Top N 段落
                                             ↓
                     LLM 结合段落生成答案 + [ID:n] 引用标注
                                             ↓
                       前端展示答案，点引用回看原文截图
```

理解了这 10 步，RAGFlow 的所有界面和 API 都只是在配置这条流水线的参数。

## 4. RAGFlow 在 RAG 工具中的定位

市面上 RAG 方案分两类：**框架**（LangChain、LlamaIndex——写代码拼装）和**开箱即用平台**（RAGFlow、Dify 等）。RAGFlow 属于后者，差异化在：

1. **深度文档理解（DeepDoc）**：用 OCR + 版面分析 + 表格结构识别三个视觉模型"看"PDF，而不是当纯文本抽——扫描件、双栏论文、复杂表格都能正确切分，且每个分块记住**页面坐标**，引用可回溯到原文截图；
2. **模板化分块**：论文、法律、简历、问答对、表格各有一套可解释的切分规则，而不是"一刀切 512 字"；
3. **有据引用**：检索侧和生成侧双重引用标注；
4. **可视化 Agent 工作流**：拖拽画布编排 LLM/工具/分支/循环，代码执行跑在 gVisor 沙箱里；
5. **生产级工程**：多租户、团队协作、30+ 数据源连接器、8 个 IM 渠道、双语言后端（Python/Go）。
